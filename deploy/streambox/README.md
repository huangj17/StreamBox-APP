# 官方片源远程更新

客户端默认读取 [sources.json](http://1.14.171.39/streambox/sources.json)。本目录的 `sources.json` 使用 `title/data` 分组数组：顶层每项是一个独立配置源，等同于在客户端添加配置源。当前包含「默认片源」内嵌 CMS 数组，以及「第三方片源」远程配置 URL。默认数组按接口去重、过滤三个旧 Bridge 条目后得到 11 个 CMS。不包含密码或管理凭据；未上传此文件时线上列表不会变化。

首次需要安装支持远程更新的客户端；之后只需修改服务器上同一个 JSON 文件。使用 `https://stvbox.cloud/streambox/sources.json` 的版本需要更新一次客户端以改回 HTTP IP 入口；升级时仅自动替换这个旧官方订阅地址，保留缓存、首页和启用偏好及自定义源。此前已使用 HTTP IP 的记录不会重复添加，也不会因曾完成 HTTPS 迁移而跳过本次迁移。此功能不更新客户端代码，不执行下载的脚本，也不要求部署 JAR Bridge。

部署前需要安装支持 `title/data` 分组格式的新客户端；旧的平铺 CMS 数组、版本对象及其本地缓存继续兼容。

## 首次部署

1. 确认 Nginx 处理 `1.14.171.39:80` 的站点及实际网站根目录（不要覆盖已有站点配置）。例如根目录若是 `/var/www/html`，文件应位于 `/var/www/html/streambox/sources.json`。该 IP 路径应直接返回 JSON，不应跳转到 `stvbox.cloud`。
2. 在本地 `client/` 目录校验待上传文件：

   ```sh
   dart run tool/validate_sources.dart ../deploy/streambox/sources.json
   ```

3. 使用已有 SSH/SFTP 或服务器管理面板，在网站根目录创建 `streambox` 子目录并上传文件。文件应允许 Nginx 读取，通常目录权限 `755`、文件权限 `644`。不要把 SSH 密码、私钥或上传权限放入 App。
4. 确认以下请求返回 HTTP 200 和 JSON，而不是登录页、404 或 HTML：

   ```sh
   curl --fail --max-time 15 http://1.14.171.39/streambox/sources.json
   ```

5. 在电视端打开「设置 → 配置源管理 → 默认片源 → 立即更新」，确认出现「默认片源」「第三方片源」分组；默认选中第一个配置源，方向键切换、确认键选择。默认分组的「详情」可查看 `groups-…` 内容版本、完整同步时间和配置地址。详情支持遥控器上下滚动，确认键或返回键关闭。

如果站点设置了长时间缓存，请给这一文件单独设置 `Cache-Control: no-cache`。客户端也会发送 `Cache-Control: no-cache`，不要让代理/CDN忽略此设置。静态文件更新不需要重启 Nginx。

## 日常维护

顶层直接使用数组，无需添加 `schemaVersion`、`version` 或 `sites` 包装。`title` 是唯一的显示名称（最长 100 字符），`data` 为 CMS 数组或公网 HTTPS 配置 URL：

```json
[
  {
    "title": "默认片源",
    "data": [
      {
        "id": "www-hongniuzy-com",
        "name": "红牛资源",
        "url": "https://www.hongniuzy2.com/api.php/provide/vod",
        "detailUrl": "https://www.hongniuzy.com",
        "isEnabled": true
      }
    ]
  },
  {
    "title": "第三方片源",
    "data": "https://9280.kstore.space/wex.json"
  }
]
```

每组在管理页单独切换，仅展示实际配置源，不额外生成「全部片源」分组；默认选中第一个配置源。内嵌组随目录更新；URL 组使用与手动添加相同的 CMS / TVBox 单仓、多仓解析流程，可独立更新、选择仓库、移除及重试，标题与缓存会持久保存。已手动添加相同 URL 时复用该配置源；主动移除后，目录自动更新不会重新添加，可通过「添加配置源」恢复。目录后来删除 URL 条目不会删除已导入的订阅。各组列表内及跨组聚合搜索仍按 CMS 接口去重，同时保留各组来源。

内嵌组通过 `title` 识别身份，调整顺序不会迁移到另一组的首页、启用偏好或历史 key；修改接口时保留组的 `title` 与片源 `id`。旧的单列表缓存升级时，按无歧义的片源 ID 迁移偏好。后台重排时，当前选中组和遥控器焦点跟随原配置源；只有原组被移除时才回到剩余组或添加入口。

当前第三方 URL（2026-10-15 核对）返回 TVBox 单仓配置，63 个站点均为 JAR 入口。只有 Android 手机 / Android TV 会显示这些站点；macOS、Windows、iOS 隐藏 JAR 站点。配置目录可在各端显示，此处只核对 JSON 结构，不代表已验证插件可播放。

内嵌数组的片源字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定唯一 ID（字母、数字、下划线或短横线，最长 80 字符），修改名称或接口时不要改 id |
| `name` | 显示名称 |
| `url` | CMS 接口；公网 HTTPS 可用；公网 HTTP 仅保留为「暂不兼容」行，不发起请求 |
| `detailUrl` | 可选字符串，仅作为元数据保留，不用于片源请求 |
| `type` | CMS 类型，支持 `0`、`1`、`3`，省略时为 `3` |
| `searchable` | 可选布尔值，默认 `true`；是否参与聚合搜索 |
| `isEnabled` | 可选布尔值，默认 `true`；`false` 表示官方停用，用户不能在客户端强行启用 |

- 每个内嵌数组是该配置源的完整片源列表，顺序就是展示顺序，不是增量补丁。无需维护版本号；客户端根据规范化内容生成 `groups-…` 标识，空白和对象字段顺序不影响标识。该标识仅供展示，不是安全签名，也不作为是否接受更新的条件。旧平铺数组仍生成 `array-…`。
- 新增：添加一个条目；下架：删除条目，或将 `isEnabled` 设为 `false`。
- 换地址：保持 `id` 不变，修改 `url`；客户端保留该片源的本地启用偏好、首页选择和历史关联 key。不同站点的影片 ID 不一定兼容，不要把旧 id 分配给完全不同的内容库。`baofeng`、`www-hongniuzy-com` 分别与旧内置暴风、红牛的身份保持一致。
- 上线前先校验，保留上一版文件作为备份；先上传临时文件，再在同一目录重命名为 `sources.json`，避免客户端下载到写了一半的内容。
- 回滚：重新发布备份内容，无需更改版本号。
- `[]` 表示明确下架全部官方片源，不会重新补回内置源。空文件、非数组内容或无效条目不会清空缓存。
- 文件上限 256 KiB，最多 200 个配置源，所有内嵌数组合计最多 200 条片源记录。单组数组里指向同一 CMS 接口的重复记录（含尾斜杠差异），在类型、启用和搜索设置一致时保留首条及其稳定身份。单组相同 ID 指向不同接口、重复接口的设置冲突、缺少必要字段、本机或私网地址、内嵌 JAR/JS 脚本等仍会导致整份拒绝，保留上次成功缓存；旧版本对象格式仍严格拒绝重复记录。合法的公网 HTTP CMS 条目会保留并标为不兼容，不影响其余 HTTPS 片源更新。

### 旧 Bridge 条目迁移

官方列表仅保留普通 CMS。旧 JVM Bridge 的 `bridge_jianpian`、`bridge_ikanbot`、`bridge_ysj`
接口即使保留在发布示例中，客户端解析时也会过滤，不会请求。
JAR 站点由 Android 本机 TVBox 配置提供，不放进这个 CMS-only 官方列表。

## 同步及离线行为

- 启动时立即提供上次成功缓存，同时后台检查更新。
- App 在前台每 30 分钟检查目录及其中已导入的 URL 配置；返回前台时距上次尝试已满 30 分钟则补查。后台停止定时请求。
- 「立即更新」不受 30 分钟间隔限制；重复点击或并发自动检查合并为一次请求。
- 下载有超时和大小限制，失败继续使用上次成功配置；从未成功同步或缓存损坏时，官方列表为空，可通过「立即更新」重试，不再自动添加暴风、红牛。自定义源仍可使用。
- URL 组下载失败只影响该组，显示自身错误并沿用自身缓存，不影响目录及其他组更新。离线重启可恢复分组标题、片源缓存、首页、启用开关和仓库选择。
- 目录更新不等待第三方配置下载，同一个 URL 的并发更新共用请求。目录错误单独保存，不会新增虚构分组；目录仅含 URL 配置源时，失败会显示「重试配置目录」，更新期间及完成后仍保留可用焦点。
- 官方配置整份替换，没有额外的内置片源列表。用户自定义配置和仓库选择不被远程删除；官方停用优先于用户的启用偏好。本次升级启动时会一次性合并已被官方缓存完整覆盖的 OuonnkiTV Lite 重复订阅，保留地址与缓存备份、首页及启用偏好；未缓存、含独有片源或已选择仓库的订阅不合并，手动重新添加后也不再自动移除。
- 已经打开的播放器持有自己的片源及播放地址快照，配置更新不会主动中断或重建播放器。变更用于后续内容浏览/搜索。

## HTTP 风险与配置地址变更

默认官方配置使用 HTTP 明文传输，不能保证传输的保密性或完整性，存在被中间人篡改的风险；页面会显示 HTTP 风险提示，建议条件允许后恢复 HTTPS。客户端允许固定的官方配置入口使用公网 HTTP；配置的每次重定向均校验目标，不允许跳到旧域名、其他 IP、端口或路径。允许同 IP 同路径升级到有效 HTTPS，但升级后不允许降级。旧 Bridge API 的兼容例外已移除。其余用户订阅、CMS 的限制不变。

证书无效或连接失败时继续使用上次成功的本地缓存，没有缓存时提示重试，不绕过证书校验。配置不应承载秘密信息。

需要使用其他配置入口时，可在构建时设置 `--dart-define=STREAMBOX_SOURCES_URL=https://你的域名/streambox/sources.json`，并为已安装版本安排地址迁移。日常修改片源本身不需要更改配置 URL 或重新安装客户端。

部署是否成功，以服务器该 URL 实际返回 HTTP 200 和有效 JSON 为准。
